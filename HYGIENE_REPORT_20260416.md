## Executive Summary

The build is functional and deployable as a thin shell, but has **four blockers** that must be resolved before inviting real users: missing PWA icon files, a broken lint pipeline, a production SQL setup file that is out of date by one migration, and unconfirmed Vercel environment variables. Beyond those, there is a concentrated set of trust/safety, performance, and accessibility gaps surfaced across two prior documents (`PRE_LAUNCH_CHECKLIST.md`, `UX_IMPROVEMENT_PROPOSAL.md`) that remain open. This report cross-references those and adds new findings from a fresh static audit.

## Phase 2 — Triage Classification

### 🔴 CRITICAL — Must fix before any public traffic

**C1. PWA icons are missing**  
`public/icons/` is empty. The manifest references two PNGs that don't exist. iOS will show a broken icon on Add to Home Screen. The `<link rel="icon">` in `index.html` also points to the missing file, so browser tab favicons are broken.  
**Action:** Generate and commit 192×192 and 512×512 PNG icons to `public/icons/`.

**C2. `npm run lint` is completely broken**  
There is no `.eslintrc.*` or `eslint.config.*` file anywhere in the project. The `lint` script in `package.json` exits with code 2. CI/pre-commit lint gates will fail or be silently skipped.  
**Action:** Add an `.eslintrc.cjs` (or `eslint.config.js`) with the React + hooks + refresh rules matching what `package.json` already has as devDependencies. This is a copy-paste from any Vite-scaffolded project.

**C3. `RUN_THIS_IN_SUPABASE_SQL_EDITOR.sql` is missing migration 011**  
The one-step setup file only runs migrations 001–010. Migration 011 (`011_replace_places_from_research.sql`) is the 8,696-line file that replaces the seed data with the actual researched places. Anyone bootstrapping a fresh Supabase project with the README instructions will get the wrong dataset.  
**Action:** Append migration 011 to the SQL runner file, or update the README to clearly require running 011 separately after the one-step file.

**C4. Vercel production environment variables — unconfirmed**  
`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and `VITE_MAPBOX_TOKEN` are listed in `.env.example` but there is no documented confirmation they are set in the Vercel dashboard for the production environment. The amber warning banner in the app will appear for any user on a misconfigured deploy — and it exposes variable names.  
**Action:** Verify all three required vars are set in Vercel → Settings → Environment Variables. Also scope the amber banner to development only (`import.meta.env.DEV`) so it never reaches production users.

### 🟠 HIGH — Serious quality / trust issues, fix before wide release

**H1. Bundle is entirely unsplit (2.2 MB / 616 KB gzip)**  
No `React.lazy`, no dynamic `import()`, no `manualChunks`. Every route loads the full bundle including Mapbox GL. Time-to-interactive on 4G will be painful.  
**Action:** Lazy-load at minimum `Map`, `PlaceDetail`, `SubmitPlace`, and `PlaceWalkthrough`. Target: get the home shell under 300 KB gzip.  
_Refs: UX IP §P3-13, PRE_LAUNCH_CHECKLIST §6_

**H2. `prefers-reduced-motion` not respected in animated components**  
`Starfield.jsx` always animates (SVG `btwink` CSS animation). `ParticleBackground.jsx` runs a rAF canvas loop unconditionally. Only `index.css` and `betweenLocal.js` have reduced-motion guards. Users with vestibular disorders or motion sensitivity will get full animation regardless of OS preference.  
**Action:** In `Starfield.jsx`, wrap the circle animation in an `@media (prefers-reduced-motion: reduce)` CSS rule (or read `matchMedia` in the component and render static circles). In `ParticleBackground.jsx`, skip the animation loop entirely when `prefers-reduced-motion` matches.  
_Refs: UX IP §P2-11_

**H3. Theophany disclaimer absent from SubmitPlace**  
`SubmitPlace.jsx` has mode selection (`sanctuary` / `theophany` / `both`) but no disclaimer appears when Theophany or Both is selected. The UX IP explicitly called this out as P0 ("every Theophany touchpoint"). Submitting supernatural/liminal place data without the same legal-adjacent framing the rest of the app shows is inconsistent.  
**Action:** Import and render `<TheophanyDisclaimer />` conditionally when `form.mode === 'theophany' || form.mode === 'both'`, positioned above the submit button. A checkbox acknowledgment is recommended but not required.  
_Refs: UX IP §P0-1_

**H4. User-facing error messages are raw for RLS failures**  
Neither `PlaceDetail.jsx` nor `SubmitPlace.jsx` surfaces friendly copy for Postgres error codes `42501` (RLS violation) or `PGRST205`. A user who hits an RLS wall or schema mismatch sees a raw technical error or silent failure.  
**Action:** In both submit handlers, check `error.code` and map `'42501'` → "We couldn't save that right now — try again in a moment." and a generic catch-all for unexpected errors.  
_Refs: UX IP §P4-17_

**H5. About and FAQ are invisible on mobile**  
`Home.jsx` renders the About/FAQ header links with `hidden sm:flex`. Mobile users have no UI path to these pages without typing the URL. If FAQ contains the AI narration disclosure and legal framing, this is a trust issue.  
**Action:** Add a minimal footer row (or hamburger/overflow menu) visible at all breakpoints linking to `/about` and `/faq`.  
_Refs: PRE_LAUNCH_CHECKLIST §3, UX IP §P1-6_

**H6. No test automation — smoke test only works locally**  
`npm run smoke` exists and is well-written, but there is no CI config (no `.github/workflows/`, no Vercel CI hook, no Playwright suite). A broken push will deploy silently to production.  
**Action (minimum viable):** Add a GitHub Actions workflow that runs `npm ci && npm run build` on every push to `main`. Optionally add `npm run smoke` if a headless preview port can be made available in Actions.  
_Refs: PRE_LAUNCH_CHECKLIST §11_

### 🟡 MEDIUM — Material UX/quality issues, fix before press/investor demos

**M1. MockAdSlot is rendering in production**  
Three "Sponsor demo" dashed-border boxes render in the live app. These are labeled correctly but will confuse first-time visitors who may believe they are real ads, or wonder why the ad slot looks broken.  
**Action:** Make a business call — hide them behind an `VITE_SHOW_AD_DEMOS=true` env flag so production is clean by default, or replace with content (a "submit a place" CTA, a mission statement callout, etc.).  
_Refs: UX IP §P4-16_

**M2. miniRoutes.js names likely broken after migration 011**  
`src/data/miniRoutes.js` resolves stops by exact `places.name` string match against the fetched places array. The hardcoded names reference migration 007 seeds. Migration 011 replaced those rows wholesale — names may have changed or rows may have been removed. Silent misses produce routes with 0 stops.  
**Action:** Run `npm run check:api` (with prod env), then manually verify that each `placeNames` entry in `MINI_ROUTES` resolves to a live row. Update or remove stale entries.  
_Refs: PRE_LAUNCH_CHECKLIST §12_

**M3. Home feed feedKind line reads as developer copy**  
The status line "Within ~350 km…" / "Catalog order…" in Home.jsx is visible to end users and reads as internal debug information.  
**Action:** Replace with user-facing language ("Showing places in PA · NJ · NY") or tuck it behind a small `?` tooltip.  
_Refs: UX IP §P1-5_

**M4. No OG / Twitter meta tags**  
`index.html` has a `<meta name="description">` but no `og:title`, `og:image`, `og:description`, `twitter:card`, or `canonical` URL. Social shares and link previews will look empty.  
**Action:** Add at minimum `og:title`, `og:description`, `og:url`, and `og:image` (a static hero image or the SVG placeholder exported as PNG) to `index.html`.

**M5. SPA route changes have no focus management**  
When navigating from Home → Place Detail or back, focus stays on the last-clicked element. Screen-reader users hear no announcement that the page changed.  
**Action:** After each route transition, call `.focus()` on the page's `<h1>` or an off-screen `<div aria-live="polite">` that announces the new page title.  
_Refs: UX IP §P2-8_

**M6. TTS Edge Function deployment unconfirmed in production**  
`supabase/functions/tts-narration/index.ts` exists and is well-implemented, but there is no documentation confirming it has been deployed (`supabase functions deploy tts-narration`) and that `OPENAI_API_KEY` has been set as a Supabase Edge Function secret. If `VITE_USE_CLOUD_NARRATION=true` is set in Vercel without a deployed function, all walkthrough narrations will silently fall back to device TTS with a confusing console error.  
**Action:** Confirm deployment status. Document the deploy step in the README or PRE_LAUNCH_CHECKLIST sign-off block.  
_Refs: PRE_LAUNCH_CHECKLIST §4_

**M7. `places_nearby` RPC and migration 009 resonance table unconfirmed in production**  
The code gracefully degrades if `places_nearby` is missing (falls back to catalog order) and if `place_resonance` is missing (suppresses the resonance button). These are silent degradations — the app "works" but with reduced functionality. It's unknown whether production Supabase has these applied.  
**Action:** Run `npm run check:api` with production credentials. Manually verify `place_resonance` table exists via Supabase Table Editor.  
_Refs: PRE_LAUNCH_CHECKLIST §4_

**M8. Mapbox token has no documented scope restrictions**  
The public Mapbox token ships in the browser bundle (expected for Mapbox GL). Without URL restrictions set in the Mapbox dashboard, the token can be used by any domain to generate billable tile requests.  
**Action:** Add allowed URLs in the Mapbox dashboard (your Vercel domain + localhost for dev).  
_Refs: PRE_LAUNCH_CHECKLIST §6_

### 🔵 LOW — Cleanup, polish, long-term hygiene

**L1. `.cursor/` directory not in `.gitignore`**  
Three `agent-images/*.jpg/.png` files are untracked and pollute `git status`. The `.cursor/` directory is IDE-local and should not be tracked.  
**Action:** Add `.cursor/` to `.gitignore`.

**L2. Google Fonts loading is render-blocking**  
`index.html` links Google Fonts with `<link href="https://fonts.googleapis.com/css2?...&display=swap">`. The `display=swap` is in the query string (handled by Google) but the connection and CSS download still delay first paint. Preconnect hints exist but the CSS is not inlined.  
**Action (low effort):** Verify `font-display: swap` is being applied by checking Chrome DevTools → Rendering → Layout Shift. If LCP is acceptable, leave as-is. Self-hosting the three fonts is the complete fix but is medium effort.

**L3. `css-animation-experiment` branch is unmerged and getting stale**  
3 commits on `css-animation-experiment` that replace place cards and activity feed photos with SVG node diagrams. If this experiment is abandoned, delete the branch. If it's a live option, it needs a decision.  
**Action:** Decide: merge, archive, or delete.

**L4. `devdir` npm config warning**  
`npm warn Unknown env config "devdir"` appears on every `npm` invocation. It's noise that makes build logs harder to read.  
**Action:** Remove the `devdir` key from your global `~/.npmrc` or Vercel environment. Not a blocker.

**L5. Place photo pipeline (migration 012) never run**  
`scripts/fetch-place-photos.mjs` is documented and working but the output file (`supabase/migrations/012_update_place_photos_from_apis.sql`) does not exist in the repo. Many places may be displaying the SVG placeholder because their `photos` column is empty.  
**Action:** Run the photo fetch script (free Wikimedia mode, no Google key needed), review the output SQL, commit as migration 012, and run it in production Supabase.
